# АгроМаркет — React

Frontend «АгроМаркета» на React + Vite. Учебный проект по дисциплине «Fullstack-разработка».

Связанные репозитории: [agromarket](https://github.com/Ferumit/agromarket) — статичная
версия и `db.json` для json-server (лаб. 1–2).

## Запуск

```bash
# окно 1 — данные: в папке agromarket (лаб. 1–2)
npx json-server --watch db.json --port 3001

# окно 2 — этот проект, http://localhost:5173
npm install
npm run dev
```

## Лабораторная 3 — компоненты, props, state, hooks

- проект создан командой `npm create vite@latest agromarket-react -- --template react`, демо-счётчик удалён;
- `src/components/ProductCard.jsx` — карточка товара, данные приходят через props (`product`, `onAdd`);
- `App.jsx`: список товаров в `useState`, загрузка с json-server в `useEffect(..., [])`, вывод через `.map()` с `key`;
- поиск — управляемый (controlled) input: значение в состоянии `searchTerm`, фильтр `.filter()` + `.toLowerCase()`;
- корзина — состояние `cartCount` в App, функция `handleAddToCart` передаётся в карточку как prop (lifting state up);
- бонус: состояния `loading` и `error`, fetch обёрнут в try/catch.

### Ответы для защиты

- **Зачем `[]` в useEffect.** Второй аргумент — список зависимостей. Пустой массив означает «выполнить
  эффект один раз, после первого рендера». Без него эффект запускался бы после каждого рендера:
  `setProducts` вызывает новый рендер, тот снова запускает fetch — бесконечный цикл запросов.
- **Что такое props.** Объект с данными, который родитель передаёт компоненту снаружи:
  `<ProductCard product={product} onAdd={handleAddToCart} />`. Компонент props только читает, не меняет.
- **Controlled input.** У обычного input значение живёт в DOM, React о нём не знает. У управляемого
  значение хранится в state (`value={searchTerm}`), а `onChange` обновляет state на каждый символ —
  React решает, что показать в поле, и может сразу использовать значение (фильтр каталога).

## Лабораторная 4 — вёрстка

Сделано: семантический каркас (`Header`, `Footer`, `main` / `section` / `aside`), `src/layout.css`
(Flexbox для шапки, панели поиска и карточки, Grid для каталога и макета), mobile-first с точками
768px и 1024px, «Товар недели» на две колонки, форма оптовой заявки `ContactForm` с HTML5-валидацией.
Бонусы: `grid-template-areas`, липкая шапка и липкая «Доставка», Lighthouse Accessibility.

Старые правила раскладки из `index.css` (`.header`, `.catalog` на flex, фиксированная ширина `.card`)
удалены: они спорили с новой сеткой. Значения ниже измерены в Chromium (DevTools / Playwright).

### Box model карточки (часть 1)
- content: 220px, padding: 16px, border: 1px, margin: 0 → итоговая ширина на экране 220 + 2·16 + 2·1 = **254px**;
- с `box-sizing: border-box` ширина стала **220px**: padding и border теперь входят в `width`, content сжался до 186px;
- в дереве ЛР3 было 5 `<div>` и ни одного семантического тега — по разметке не понять, где шапка, где каталог.
  После ЛР4: `header`, `nav`, `main`, 2 × `section`, `aside`, `footer`, `address`, 12 × `article`, `<div>` осталось 3.

### repeat(4, 1fr) на узком экране (часть 4)
На ширине 500px четыре колонки не помещаются: колонка `1fr` не может стать уже содержимого карточки
(длинное слово в названии, кнопка), поэтому сетка вылезает за экран — ширина страницы 737px при окне 500px,
третья и четвёртая колонки уходят вправо, появляется горизонтальная прокрутка, карточки разной ширины.

### auto-fit vs auto-fill (часть 4)
При поиске «мол» (2 товара) на 1280px: с `auto-fit` карточки растянулись до 443px — пустые колонки
схлопываются, и два товара делят весь ряд; с `auto-fill` карточки остались 289px — пустые колонки сохраняются.
Выбран `auto-fill`: карточки одного размера при любом числе результатов поиска.

### «Товар недели» на телефоне (часть 4)
С `grid-column: span 2` без media query на 375px сетка из одной колонки достроила вторую
(`220px 153.875px`), и страница стала шире экрана (410px) — горизонтальная прокрутка. Исправлено: `span 2`
внутри `@media (min-width: 768px)`.

### Форма заявки (часть 6)
Пустая форма не отправляется: браузер показывает подсказку «Заполните это поле» у имени, email и объёма
(в англоязычном Chrome — *Please fill out this field*). Email без «@» и объём 5 кг тоже останавливают
отправку (*Please include an '@'…*, *Value must be greater than or equal to 10*),
у неверного поля после ввода красная рамка (`:user-invalid`). Верно заполненная форма → alert и очистка полей.

### Бонус: Lighthouse
Accessibility: **93** → **100**. Единственное замечание — контраст плашки «Корзина»
(белый текст на полупрозрачном белом поверх зелёного, 3.82 при норме 4.5). Фон сделан тёмно-зелёным `#1b5e20`.

### Ответы для защиты
1. **section и article.** `<section>` — тематический раздел страницы со своим заголовком (каталог, форма).
   `<article>` — самостоятельный блок, который имеет смысл сам по себе, даже вырванный из страницы.
   Карточка товара самодостаточна (картинка, название, цена, кнопка), поэтому `ProductCard` — `<article>`.
2. **Один main.** `<main>` — основное содержимое документа, оно у страницы одно (для скринридера это точка
   «перейти к содержимому»). Разделов (`<section>`) внутри может быть сколько угодно.
3. **box-sizing: border-box.** `width` начинает включать padding и border. Без него к 220px добавились бы
   2·16 + 2·1 и карточка стала бы 254px — шире, чем задано.
4. **Flexbox и Grid.** Шапка — один ряд элементов (одно измерение) → Flexbox. Каталог — строки и колонки
   одновременно (два измерения) → Grid.
5. **repeat(auto-fit, minmax(220px, 1fr)).** Уместить столько колонок, сколько влезет, каждая не уже 220px,
   свободное место поделить поровну. Число колонок меняется само, без media query.
6. **Mobile-first.** Базовые стили пишутся для телефона, а для больших экранов макет «достраивается»
   через `@media (min-width: …)`: правило включается начиная с этой ширины и выше. `max-width` нужен
   при обратном подходе — от десктопа к телефону.
7. **label htmlFor и type="email".** Связка `<label htmlFor="email">` + `<input id="email">`: клик по подписи
   ставит курсор в поле, скринридер читает подпись. `type="email"` даёт встроенную проверку формата
   и клавиатуру с «@» на телефоне.
